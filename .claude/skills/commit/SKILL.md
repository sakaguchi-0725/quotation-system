# Commit

作業中の変更をこのリポジトリのコミットルールに沿ってコミットするためのスキル。ルールを暗黙知のまま毎回思い出すのではなく、`references/commit-rules.md` に固定化されたルールを参照することで、誰が実行しても同じ品質のコミットメッセージになるようにする。

## 進め方

### 1. diffの確認

まず現在の変更内容を把握する。

```bash
git status
git diff
git diff --staged
```

- 変更が何もなければ、その旨をユーザーに伝えて終了する(コミットを作らない)。
- diffの中に**複数の論理的変更単位**(例: 機能追加とフォーマット変更、無関係な2つの修正)が混在している場合は、`references/commit-rules.md` の Atomic Commits の原則に従い、コミットを分割する。分割が必要な場合 `git add` で対象ファイル・ハンクを絞り込みながら複数コミットに分ける。
- 作成予定のコミットをユーザーに報告し、y / n で許可を得る。

### 2. コミットルールに基づきコミットを作成

`references/commit-rules.md` を読み、そこに書かれているルールと末尾のチェックリストに従ってコミットメッセージを組み立てる。

```bash
git commit -m "$(cat <<'EOF'
<type>(<scope>): <件名>

<本文>
EOF
)"
```

ユーザーから明示的な許可なく、`--no-verify` や `--amend` などの安全装置を回避するオプションは使わない。pre-commitフックが失敗した場合は原因を修正し、新規コミットとしてやり直す。

### 3. 完了報告

コミット作成後、`references/report-format.md` のフォーマットに従ってユーザーに報告する。
